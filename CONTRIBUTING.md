# Contributing to 3DKenji

Thank you for considering contributing to 3DKenji. This file highlights how to get started.

## Get set up
- Follow the repository setup guide: .github/SETUP_GUIDE.md
- See `docs/getting-started.md` for local and Docker instructions

## Workflow
- Branch from `dev` using `feature/*`, `bugfix/*`, `docs/*`, or `chore/*` prefixes
- Open a pull request to `dev` when ready
- Ensure CI passes and address review comments
- For bugs, open a GitHub Issue and use a branch name like `bugfix/<issue-number>-<short-slug>`

## Code style and tests
- Run tests before creating a PR: `make test`
- Keep changes focused and add tests for new behavior

## Documentation
- Update docs in `/docs/` for any behavioral or config changes

## Questions
- Open an issue or discussion on GitHub

> **Note**: As of v1.0.0, GitHub Issues are the system of record for bug tracking.
